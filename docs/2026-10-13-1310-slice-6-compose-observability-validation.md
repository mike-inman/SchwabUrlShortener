## Implementation

- `compose.yaml` defines PostgreSQL, Redis, Kafka, a one-shot Kafka topic initializer, one-shot EF migration, API, Web, Analytics, and Caddy. PostgreSQL/Redis/Kafka/Caddy/API/Web/Analytics have bounded health probes; API waits for migrations, Redis, and Caddy; Web waits for healthy API; Analytics waits for migrations and topic creation. Kafka auto-topic creation is disabled. The local topic has three partitions and one replica, appropriate only for a single local broker.
- API readiness checks migrations/PostgreSQL and Redis. Web readiness checks its internal API's readiness. Analytics readiness checks PostgreSQL and the configured Kafka topic. Missing required API/worker configuration names the setting and exits; an unreachable broker makes the worker probe fail. Startup and stopping events carry a service field in JSON console logs. EF command information logging is filtered from API output, and the two Web UI error paths log exception type instead of full exception objects. API/Web data-protection keys use persistent named Docker volumes. API and Analytics runtime images include Ubuntu's `libgssapi-krb5-2` so the PostgreSQL client's optional native-library warning no longer appears on startup.
- `compose.test.yaml` adds a test-only `Schwab_test_local` database, a separate migration, and a source-only test image. The test factory refuses other database names. The test profile must be used only with a fresh disposable Compose project because those tests truncate its guarded database tables.
- API accepts its public host and the private `api` service host. This fixed the Web-to-API calls uncovered by the Web readiness probe while keeping other hostnames rejected. Public URLs still come from `PublicLinks:BaseUrl`, independently of `http://api:8080/`.
