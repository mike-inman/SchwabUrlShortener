# Secret rotation runbook — 2026-10-13 19:35 CDT

Scope: private `prod` azd inputs and Key Vault secrets. Never put a value in chat, shell history, Git, deployment output, or a runbook. Confirm account/subscription and obtain an incident or scheduled-change approval. Preserve old versions until the new version works. This procedure has not been exercised against Azure.

- **PostgreSQL password:** create a replacement password privately and change the server administrator credential during a controlled window. Update the local secure `POSTGRES_PASSWORD` azd value and publish new `pg-app-connection` and `pg-migrate-connection` Key Vault versions. Keep `Maximum Pool Size=2` on the app connection. Restart API, Analytics, and the migration job reference; verify private TLS connectivity and health. Confirm later Bicep runs use the replacement password.
- **Redis password:** generate privately, update the Redis server setting and local secure `REDIS_PASSWORD`, then publish new `redis-password` and `redis-connection` versions together. Restart Redis and its clients in a controlled order. Verify redirects and cached token behavior; expect cache repopulation. Preserve the Azure Files AOF and do not delete local passwords.
- **Event Hubs SAS key:** use the secondary key first: regenerate it, publish a new `eventhubs-connection` version, switch API/Analytics, and verify publish/consume. Only then regenerate the former primary key. Keep the authorization rule at Send/Listen. Update any deployment source-of-truth logic so a later provision does not overwrite the chosen key with an older one.
- **Web Entra client secret:** before its 180-day expiry, create a new secret on the existing Web registration, enter it privately into `WEB_CLIENT_SECRET` in `prod`, publish a new `web-client-secret` Key Vault version, restart Web, and verify sign-in and downstream API calls. Remove the old registration secret only after validation. If managed-identity federation is proven and adopted in P2, remove the Azure client-secret dependency in a separate approved change while retaining the local development credential.

For each rotation, record the secret **name**, version identifier, affected apps, start/end time, and verification outcome; never record the value. Container Apps Key Vault references must be checked after restart. A P1/P2 Bicep redeploy can write a new version from azd inputs, so keep those inputs synchronized with the current credentials.
